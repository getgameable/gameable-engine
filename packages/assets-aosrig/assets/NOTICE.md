## Changes from the upstream models

As Apache-2.0 section 4(b) asks, the modifications are stated here:

- The MHR LOD1 body and the GNM V3 head are joined into one mesh with two
  primitives (`body`, `head`) sharing one vertex buffer.
- The skeleton is MHR's, with the GNM head joints attached; skin weights are
  reduced to the top four influences per vertex and renormalised.
- Four looping clips (`idle`, `walk` at 1.4 m/s, `run` at 3.6 m/s, `wave`) are
  baked through MHR's forward kinematics, so its 34 `*_proc` twist joints are
  correct.
- The result is written as glTF 2.0 binary, Y-up, +Z forward, feet at `y = 0`,
  1.73 m tall, with no textures and no Draco.

## What the file is

| Property   | Value                                                           |
| ---------- | --------------------------------------------------------------- |
| Format     | glTF 2.0 binary, no textures, no Draco                          |
| Size       | ≈ 3.1 MB                                                        |
| Geometry   | Two primitives (`body`, `head`) sharing one vertex buffer       |
| Skeleton   | 114 joints, Y-up, +Z forward, feet at `y = 0`, 1.73 m tall      |
| Skinning   | Linear blend, top-4 influences, renormalised                    |
| Animations | `idle`, `walk` (1.4 m/s), `run` (3.6 m/s), `wave` — all looping |

It is not generated by anything in this repository, so it is a committed input
here rather than a build output: `npm run generate` does not rebuild it.
`src/pack.test.ts` is the contract with the exporter. If the joint order
changes, a clip goes missing or a locomotion clip is rebaked at a different
speed, that test goes red.

## Using it

Ship this file, `NOTICE.md` and `LICENSE-APACHE-2.0.txt` together whenever you
redistribute the rig. A game that loads it at runtime needs nothing extra.
